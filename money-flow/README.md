# Money Flow — วิเคราะห์เส้นทางเงินจาก statement ธนาคาร

เว็บแอปสำหรับรันบนเครื่องตัวเอง แปลงไฟล์ CSV จากธนาคารหรือบัตรเครดิตเป็นกราฟเครือข่าย (link analysis แบบ i2 Analyst's Notebook) จะเห็นว่าเงินไหลไปหาใคร รับมาจากใคร และโอนระหว่างบัญชีตัวเองอย่างไร

**ความเป็นส่วนตัว:** ทุกอย่างทำงานใน browser ไม่มี backend และ production build ตั้ง CSP เป็น `connect-src 'none'` คือห้ามส่ง network request ใดๆ ออกไปเลย ที่บันทึกไว้ใน localStorage มีแค่รูปแบบคอลัมน์ของแต่ละธนาคารกับชื่อที่เปลี่ยนเอง ส่วนรายการ transaction อยู่ในหน่วยความจำเท่านั้น ปิดแท็บแล้วหายหมด

## เปิดแอปแบบง่าย (Windows)

1. ติดตั้ง [Node.js LTS](https://nodejs.org) (ครั้งเดียว)
2. ในโฟลเดอร์ `money-flow` ดับเบิลคลิก **`Create Desktop Shortcut.bat`** จะได้ไอคอน **Money Flow** บน Desktop
3. ครั้งต่อไปดับเบิลคลิกไอคอนนั้น เบราว์เซอร์จะเปิดให้เอง หน้าต่างสีดำต้องเปิดค้างไว้ ปิดหน้าต่าง = ปิดแอป
4. อัปเดตเป็นเวอร์ชันใหม่: ดับเบิลคลิก **`Update Money Flow.bat`** ตัวเปิดแอปไม่ดึงโค้ดใหม่เอง เพื่อไม่ให้มีโค้ดใหม่รันโดยคุณไม่รู้

ตัวเปิดแอปรันเวอร์ชัน production ที่ `http://127.0.0.1:5173` ซึ่งมีการป้องกันดังนี้:
- ฟังเฉพาะ `127.0.0.1` เครื่องอื่นใน Wi-Fi เดียวกันเปิดไม่ได้
- CSP `connect-src 'none'` แอปส่ง request ออกเน็ตไม่ได้เลย
- ห้ามฝังในเว็บอื่น (`frame-ancestors 'none'`, `X-Frame-Options: DENY`) ปิด camera, mic, location, payment และไม่ cache หน้าเว็บ (`no-store`)

## หน้า "สรุป"

หน้าแรกหลังโหลดไฟล์:
- **รายรับ / รายจ่ายจริง / ลงทุน / เหลือสุทธิ** "รายจ่ายจริง" ไม่รวมเงินที่ส่งไปลงทุน (Coinbase ฯลฯ) และเงินที่โอนระหว่างบัญชีตัวเอง
- **สิ่งที่ควรรู้** ข้อสังเกตภาษาไทยที่ระบบสรุปให้: ใช้จ่ายเกินรายรับ, ค่า AI/สมาชิกต่อปี, สมัครบริการเดียวกัน 2 ช่องทาง, โดนตัดเงิน 2 ครั้งใน 7 วัน, ซื้อของเล็กๆ บ่อย, หมวดที่เพิ่มขึ้นจากเดือนก่อน, ราคาขึ้น, ตัดเงินซ้ำ, เงินสด, เงินลงทุน
- **จ่ายไปกับอะไร** จัดหมวดอัตโนมัติ 26 หมวด กดดูรายชื่อในหมวดได้ ถ้าจัดหมวดผิด เลือกหมวดใหม่ได้ ระบบจะจำไว้
- เทียบกับเดือนก่อนเฉพาะเมื่อเดือนก่อนมีข้อมูลอย่างน้อย 20 วัน เพื่อไม่ให้ขึ้นตัวเลขหลอกอย่าง "+700%"

## รอบ statement, งบประมาณ, เงินสำรองฉุกเฉิน

- **เริ่มรอบวันที่**: เมื่อนำเข้า PDF ระบบจะตั้งรอบตาม statement ให้เอง (เช่น Chase 24 → 23) statement 1 ใบจึงเป็น 1 รอบเต็ม และตัวเลขตรงกับใบ statement ถ้าเลือก 1 จะดูตามเดือนปฏิทิน เมื่อเลือกเองแล้ว ระบบจะไม่เปลี่ยนให้อีก
- **งบประมาณต่อรอบ**: ตั้งงบรายหมวด ระบบแนะนำตัวเลข (90% ของค่าเฉลี่ยรอบที่ข้อมูลครบ) แถบแสดงสถานะ อยู่ในงบ / ใกล้เต็ม / ถ้าใช้อัตรานี้จะเกิน / เกินแล้ว ระบบเริ่มคาดการณ์หลังมีข้อมูลรอบนั้น 7 วัน และเตือนเมื่อคาดว่าจะเกินงบมากกว่า 10% ข้อสังเกตที่เกี่ยวกับงบจะขึ้นใน "สิ่งที่ควรรู้" ด้วย
- **เป้าเงินสำรองฉุกเฉิน**: ใส่เป้าหมาย (ค่าแนะนำ = รายจ่ายจริง 6 เดือน) และยอดที่มีอยู่ ระบบคำนวณว่าถ้าเก็บได้เท่าค่าเฉลี่ย "เหลือสุทธิ" ของรอบที่ข้อมูลครบ จะถึงเป้าในอีกกี่เดือน
- งบ เป้าหมาย และวันเริ่มรอบ เก็บใน localStorage ของเบราว์เซอร์บนเครื่องนี้เท่านั้น

## ไฟล์แบบ "จาก → ไป" (เครือข่ายเงิน)

ไฟล์ที่ระบุผู้จ่ายและผู้รับในแต่ละแถว เช่น Venmo, PayPal หรือ Excel ที่จดเอง (`วันที่, จาก, ไป, จำนวนเงิน, หมายเหตุ`) ทำให้กราฟเป็นเครือข่ายจริง ไม่ใช่รูปดาว
- ระบบตรวจคอลัมน์ From/To (Sender/Recipient, จาก/ไป, ผู้โอน/ผู้รับ) และข้ามบรรทัดหัวเรื่องด้านบนให้เอง
- **ชื่อคุณในไฟล์นี้**: แถวที่มีชื่อคุณ = เงินเข้า/ออกของบัญชีนั้น (นับในหน้าสรุป) · แถวระหว่างคนอื่น = แสดงในกราฟเท่านั้น
- ระบบจะเดาชื่อคุณให้เฉพาะเมื่อชื่อนั้นอยู่ในอย่างน้อย 90% ของแถว (เช่น export Venmo ของตัวเอง) เพื่อไม่ให้นับเงินของคนอื่นเป็นของคุณ
- Venmo: ใช้เครื่องหมาย +/− ในไฟล์ตัดสินทิศทาง (รายการ "Charge" ระบุผู้เรียกเก็บเป็น From)
- ชื่อในไฟล์ที่ตรงกับชื่อบัญชีในแอป จะต่อเส้นเข้ากล่องบัญชีนั้น
- ตัวอย่าง: `samples/venmo-sample.csv`, `samples/links-sample.csv` (ข้อมูลสมมติ)

## คริปโต: ตามเส้นเงินบน blockchain

ข้อมูล blockchain เป็นข้อมูลสาธารณะ จึงตามเส้นเงินของ address ใดก็ได้อย่างถูกกฎหมาย
1. ใน explorer (etherscan.io, basescan.org, polygonscan.com, explorer ที่ใช้ Blockscout ฯลฯ) เปิดหน้า address → **Export CSV**
2. ลากไฟล์ใส่แอป ระบบตรวจว่าเป็นไฟล์คริปโต (มีคอลัมน์ From/To ร่วมกับ Value_IN/Value_OUT หรือ TokenSymbol หรือค่าในคอลัมน์ From/To เป็น address)
   - เหรียญอยู่ในหน่วยของมัน (ETH, USDC…) **ไม่รวมกับดอลลาร์** และไม่นับในหน้าสรุป
   - address ที่อยู่ในเกือบทุกแถว = กระเป๋าที่ export มา แสดงเป็นกล่องสีน้ำเงิน และเปลี่ยนชื่อได้
   - ข้ามรายการที่ล้มเหลว (Status/ErrCode) และรายการมูลค่า 0 (approve / contract call)
3. ตามเงินต่อหลายทอด: export address ปลายทางมาใส่เพิ่ม กราฟจะเชื่อมกันเอง รายการเดียวกัน (hash เดียวกัน) นับครั้งเดียว

ข้อจำกัด: ยังไม่แปลงเป็นดอลลาร์ ไม่นับค่า gas ไม่รวม internal transactions และ Bitcoin/Chia (โมเดล UTXO/coin) export ออกมาเป็น "จาก → ไป" ไม่ตรงแบบ Ethereum ไฟล์ตัวอย่าง (address สมมติ): `samples/crypto-*.csv`

## ชื่อ address, ป้ายบทบาท, ตามรอยเงิน

- **ค้นหา**: ช่อง 🔍 บนแถบตัวกรอง รับ address ที่วางมาทั้งตัว บางส่วน หรือชื่อ
- **สมุดรายชื่อ address**: ตั้งชื่อและประเภทได้จากแผงด้านขวา (🔑 ของฉัน, 👤 คน, 🏪 ร้าน, 🏦 exchange, 🌀 mixer, 🌉 bridge, 📜 contract) หรือลากไฟล์ `address,name,type` (ใช้หัวคอลัมน์ไทยได้) ป้ายชื่อในไฟล์ export (ถ้ามี) จะถูกเพิ่มให้เอง โดยไม่ทับชื่อที่คุณตั้งไว้ เก็บใน localStorage ของเครื่องนี้ ส่งออก/ล้างได้ที่แท็บ "รวมชื่อ"
- ในกราฟ แต่ละประเภทมีรูปทรงต่างกัน (exchange = หกเหลี่ยม, mixer = แปดเหลี่ยมสีดำ และเส้นที่เข้า mixer เป็นเส้นประ)
- **ป้ายบทบาทอัตโนมัติ** (เดาจากข้อมูลที่ใส่ ไม่ใช่หลักฐาน):
  - ⚡ **ส่งต่อเร็ว**: รับแล้วส่งต่อ ≥ 80% ของยอดภายใน 24 ชั่วโมง
  - 🆕 **ใช้ครั้งเดียว**: รับ 1 ครั้ง ส่งออก ≤ 1 ครั้ง
  - 🏦 **น่าจะเป็น exchange**: มีคู่ค้า ≥ 8 ราย
  - 🌀 **mixer**: มาจากสมุดรายชื่อ
- **ตามรอยเงิน**: ไล่ทอดไปข้างหน้าตามเวลา โดยหลังเงินมาถึงจุดหนึ่ง เฉพาะรายการที่ออกทีหลังและเป็นเหรียญเดียวกันเท่านั้นที่นับเป็นทอดต่อไป เลือก 3 รายการใหญ่สุดต่อเหรียญ ไม่เกิน 6 ทอด หยุดที่ mixer, exchange, จุดที่วนกลับ หรือจุดที่ไม่มีข้อมูล (พร้อมลิงก์ export ที่ Etherscan) เส้นทางจะไฮไลต์สีส้มในกราฟ
- ข้อจำกัด: การแลกเหรียญ (เช่น ETH → USDC) ทำให้เส้นทางขาด เพราะระบบตามเฉพาะเหรียญเดียวกัน ระบบไม่ได้เดาว่าเงินที่ออกจาก mixer เป็นของใคร (ตั้งใจไม่ทำ เพราะเสี่ยงกล่าวหาผิดคน)

## ธนาคารไทย + ตัวอย่าง "มูลนิธิ" (ข้อมูลสมมติ)
- อ่านวันที่ พ.ศ. (`05/03/2567`, `5 มี.ค. 67`) และหัวคอลัมน์ไทย `วันที่, เวลา, รายการ, ถอนเงิน, ฝากเงิน, ยอดคงเหลือ, รายละเอียด`
- PDF ไทย: อ่าน `ยอดยกมา/ยอดยกไป` แล้วใช้ยอดคงเหลือเดาเครื่องหมาย +/− (ยังไม่ได้ทดสอบกับ PDF จริงของทุกธนาคาร)
- ชื่อคู่โอนจะถูกตัดคำว่า โอนเงิน/พร้อมเพย์/รหัสธนาคาร/เลขบัญชี/คำนำหน้า ออกก่อน เพื่อให้คนเดียวกันรวมเป็นจุดเดียว
- สกุลเงิน ฿/$: สลับได้ที่ปุ่มบนแถบด้านบน ถ้าไฟล์เป็นภาษาไทย ระบบจะเปลี่ยนเป็นบาทให้เอง
- ตัวอย่างในโฟลเดอร์ `samples/th/` (ชื่อทั้งหมดเป็นชื่อสมมติ): `foundation-A-bank.csv` (บัญชีมูลนิธิ 1 ปี), `investigation-ledger.csv` (บัญชีจาก → ไป ที่จดจากหลักฐาน), `address-book-th.csv`
- 💵 เงินสด: การตามรอยหยุดเมื่อเงินถูกถอนเป็นเงินสด เพราะไฟล์ไม่มีข้อมูลต่อจากนั้น

## ใช้ PDF statement ได้เลย

ลาก **PDF statement** จากธนาคาร (ทดสอบกับ Chase checking แล้ว ธนาคารอื่นที่หน้าตาคล้ายกันมักใช้ได้) ใส่ได้ทีละหลายไฟล์ แอปจะ:
- อ่าน PDF ใน browser ด้วย pdf.js ที่ bundle มาในแอป ไม่ส่งไฟล์ไปไหน
- ตรวจ **ยอดยกมา + รายการทั้งหมด = ยอดปลายงวด** และเทียบยอดคงเหลือทีละบรรทัด ถ้าตรงจะขึ้น ✓ PDF reconciles สีเขียว
- ตั้งชื่อบัญชีให้อัตโนมัติ (เช่น `Chase College Checking …3719`) **ใช้ชื่อเดียวกันทุกเดือน ข้อมูลจะรวมเป็นบัญชีเดียว** รายการที่ซ้ำกัน (โหลดไฟล์เดิมซ้ำ) จะถูกข้าม
- PDF ที่เป็นภาพสแกนอ่านไม่ได้ ให้โหลด CSV แทน

ข้อควรระวัง: อย่าใส่ทั้ง CSV และ PDF ของเดือนเดียวกันในบัญชีเดียวกัน คำอธิบายรายการในสองแบบไม่เหมือนกัน แอปจึงจับซ้ำไม่ได้ และจะนับซ้ำ

## ขั้นตอนใช้งาน

1. **+ Add CSV** หรือลากไฟล์มาวาง (ใส่หลายไฟล์ได้ 1 ไฟล์ = 1 บัญชี) ถ้ายังไม่มีไฟล์ กด *Try with anonymized sample files* เพื่อลองก่อนได้
2. **Map columns** เลือกคอลัมน์ วันที่ / คำอธิบาย / จำนวนเงิน (คอลัมน์เดียวแบบ +/− หรือแยก debit/credit)
   - บัตรเครดิตที่แสดงยอดซื้อเป็นบวก (Amex, Discover ฯลฯ) ให้ติ๊ก **Flip sign**
   - ติ๊ก *Remember this layout* แล้วตั้งชื่อ ครั้งหน้าถ้า header ตรงกัน แอปจะจำได้เอง
   - อัปโหลดไฟล์เดิมซ้ำ รายการจะไม่ถูกนับซ้ำ (dedupe ด้วย id)
3. **กราฟ** สี่เหลี่ยมสีน้ำเงิน = บัญชีคุณ, วงกลมเขียว = แหล่งเงินเข้า, แดง = ที่เงินออกไป, ส้ม = มีทั้งเข้าและออก, เส้นม่วง = โอนระหว่างบัญชีตัวเอง label บนเส้นคือ `จำนวนครั้ง / ยอดรวม` ความหนาเส้นตามยอดเงิน คลิก node หรือเส้นเพื่อดูรายการ
4. **Names tab** รวมชื่อที่เป็นเจ้าเดียวกัน หรือเปลี่ยนชื่อ
   - **สำคัญ:** รายการโอนระหว่างบัญชี (เช่น `TRANSFER SAV 7788`, `AMEX EPAYMENT ACH PMT`, `CARD PAYMENT RECEIVED`) ให้ merge เข้าชื่อ **บัญชีของคุณ** แล้วแอปจะจับคู่ฝั่งออกกับฝั่งเข้า (ยอดเท่ากัน ห่างกันไม่เกิน 5 วัน) และนับแค่ครั้งเดียว
5. **Side panel**: Overview (ยอดรวมต่อบัญชี + top in/out), Monthly, Recurring (subscription/ค่าใช้จ่ายประจำ + เตือนเมื่อราคาขึ้น), Duplicates (ตัดเงินซ้ำวันเดียวกันหรือห่างกันไม่เกิน 2 วัน)
6. **Filters**: ช่วงวันที่, ยอดขั้นต่ำ, เข้า/ออก, เลือกบัญชี, Top N (ที่เหลือรวมเป็น node OTHER ยอดรวมจึงไม่หาย)
7. **Export**: PNG ของกราฟ, Summary CSV (สรุปต่อคู่ค้า), Txns CSV (ทุกรายการพร้อมชื่อที่ normalize แล้ว เปิดใน Excel ได้) ตัว export ป้องกัน CSV/formula injection ไว้แล้ว

## วิธีตรวจว่าตัวเลขถูก

ตาราง **Accounts** ใน Overview เป็นยอดดิบ (ยังไม่ได้ตัด transfer) ต้องตรงกับ statement เอาไปเทียบได้เลย:
`ยอดยกมา + Net = ยอดคงเหลือปลายงวด` (มีชุดทดสอบที่เช็คสูตรนี้กับไฟล์ตัวอย่าง)

## ข้อจำกัดที่ควรรู้

- ถ้าใช้แค่ statement ของตัวเอง กราฟจะเป็นรูปดาว (บัญชีคุณอยู่กลาง) เพราะไม่เห็นว่าปลายทางโอนต่อไปไหน ใส่หลายบัญชีพร้อมกันจะเริ่มเห็นเส้นเชื่อมระหว่างบัญชีมากขึ้น
- การ normalize ชื่อเป็น heuristic ร้านเล็กๆ ที่มีชื่อเมืองต่อท้าย (เช่น `THAI BASIL CAFE HOUSTON`) อาจต้องรวมเอง
- Recurring ต้องมีข้อมูลอย่างน้อย 3 เดือนจึงจะแม่น payroll ที่ตัด 2 ยอดในวันเดียวกัน (NET + TAX) จะไม่ถูกจับเป็น recurring เพราะยอดต่างกันมาก
- รองรับรูปแบบตัวเลขแบบ US เท่านั้น (`1,234.56`) ยังไม่รองรับ PDF
